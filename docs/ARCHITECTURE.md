# Архитектура

AIHub Remote Agent — Node.js-сервер MCP по stdio. Клиент может запускать его непосредственно или через отдельно настроенный туннель. Сам агент не открывает публичный HTTP-порт. Облачная привязка, аутентификация и транспорт туннеля принадлежат используемому tunnel-клиенту.

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| `server/index.mjs`, `mcp-server.mjs` | Запуск, MCP-протокол, каталог инструментов, обработка запросов |
| `config.mjs`, `path-policy.mjs` | Локальная конфигурация и канонические разрешённые пути |
| `tools.mjs` | Файлы, процессы, диагностика и Codex-инструменты |
| `process-manager.mjs`, `output-buffer.mjs`, `wsl-control.mjs` | Собственные процессы, ограниченный вывод, идентификация WSL-процессов |
| `codex-bridge.mjs` | Обёртка над внешними Codex Connect/UI-скриптами и долговременные квитанции отправки |
| `mcp-registry.mjs` | Чтение выбранных локальных определений MCP, регистрация ссылок и отпечатков |
| `mcp-client.mjs`, `local-mcp-bridge.mjs` | Соединения с зарегистрированными MCP, сериализация запросов одного сервера |
| `mcp-operation-store.mjs`, `mcp-reply.mjs` | Квитанции до отправки, сохранённые результаты и нативные content blocks |
| `launcher/` | Версионная установка, запуск, остановка, статус и откат Windows-экземпляра |
| `skills/remote-machine/` | Маршруты работы агента с подключённой машиной |

## Локальные MCP

Регистрация читает явно выбранное определение и сохраняет ссылку на источник с отпечатком. Она не запускает сервер. Запрос каталога или другого метода устанавливает соединение и может запустить описанный stdio-процесс. При изменении определения требуется явная перерегистрация; инструментальные ограничения источника сохраняются.

Операция `tools/call` получает уникальный `operation_id`. Хранилище сохраняет подготовку и признак отправки до сетевого/stdio-вызова. Повтор того же запроса с тем же ID читает квитанцию; несовместимое использование ID отклоняется. У неизвестного исхода нет автоматического повтора. Это защита на стороне моста, а не распределённая гарантия «ровно один раз» внутри стороннего приложения.

Изображения, аудио и ресурсы передаются как MCP content blocks, с отдельными метаданными операции. URI ресурса передаётся выбранному MCP-серверу; агент не превращает его в произвольное чтение локального файла или URL.

## Состояние и конфиденциальность

Конфигурация, журналы, регистрации и квитанции находятся вне репозитория. По умолчанию используется каталог данных пользователя: `%LOCALAPPDATA%\AIHubRemoteAgent` в Windows или `~/.aihub-remote-agent` на другом хосте. Переменные `AIHUB_REMOTE_AGENT_CONFIG` и `AIHUB_REMOTE_AGENT_STATE` позволяют выбрать собственные расположения.

Обычные process sessions существуют в памяти текущего процесса. Квитанции MCP и Codex сохраняются на диске. Сырые результаты и вывод дочерних процессов могут содержать личные данные; их нельзя включать в публичный пакет. После перезапуска неопределённые операции требуют сверки, а не повторного выполнения.

## Граница совместимости

WSL и Codex Connect — отдельные интеграции. Ядру они не нужны. Codex-обёртка не реализует собственный backend и не включает внешние скрипты в поставку. Поддерживаемые MCP-транспорты и версии перечислены в [документации моста](LOCAL_MCP_RU.md); границы доверия — в [SECURITY.md](SECURITY.md).
