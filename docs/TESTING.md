# Проверка изменений

## Базовые проверки

Из корня репозитория:

```bash
npm test
npm run check:privacy
npm run check:routes
npm run build:manifest
npm run validate
node server/index.mjs --self-test
```

Сервер не требует установки npm-зависимостей. Команда `npm test` запускает Node.js test runner и синтетические fixtures. Манифест нужно пересобрать после окончательных правок релизных файлов. Его проверка относится к целостности пакета, а не к авторству.

## Что покрывают тесты

| Область | Сценарии |
| --- | --- |
| Файлы и конфигурация | Разрешённые корни, canonical paths, SHA-правки, отдельные настройки интеграций |
| Процессы | Вывод, offsets/обрезка, ошибки запуска, собственные sessions, остановка |
| MCP-клиент | Initialize, версии, framing, JSON/SSE, ограничения ответа, timeout, отсутствие автоматического replay |
| MCP registry | Поддерживаемые конфиги, fingerprint, импорт ограничений, безопасные метаданные |
| MCP операции | Состояния до/после dispatch, dedup, конфликт ID, перезапуск, повреждённые записи |
| MCP мост | Настоящие схемы fixtures, внутренние процессы, content blocks и lifecycle |
| Codex | Синтетические discovery/read/preflight/delivery, receipt и запрет повторной отправки |

Количество тестов и платформенные skips берите из фактического запуска для конкретного коммита. Не копируйте старый счётчик в новый отчёт как свидетельство текущего состояния.

## Проверки целевой платформы

Для Windows используйте `node scripts/smoke-windows.mjs`; `--wsl` добавляет WSL-проверки. `node scripts/smoke-mcp-wsl.mjs` проверяет синтетический MCP через WSL. Оба используют приватную WSL-конфигурацию либо явно заданную пару `--wsl-distro` / `--wsl-user`. `scripts/smoke-install.ps1` проверяет Windows-установщик. Изучите параметры и предусловия перед запуском. Отсутствие Windows или настроенного WSL означает «не выполнено», а не «пройдено».

`smoke-local-mcp.mjs` требует `--source` и `--server`; необязательны `--runtime native|windows|wsl`, повторяемый `--read-root`, `--tool` и `--arguments-json`. По умолчанию запрашивается только каталог. Скрипт предназначен для выбранного реального MCP и содержит ограниченный набор диагностических чтений. Даже catalog-only проверка может запустить его stdio-процесс. Запускайте такой smoke только для разрешённого приложения/стенда и не публикуйте сырой отчёт без очистки.

Приёмка Codex UI и туннеля отдельно описана в [Codex compatibility](CODEX_CONNECT_COMPATIBILITY.md) и [installation](INSTALLATION.md). CI не отправляет реальные сообщения и не использует рабочие токены.

## Отчёт о проверке

Укажите commit, версию, ОС и Node.js, выполненные команды, итог и пропуски. Достаточно краткой очищенной сводки. Не прикладывайте локальные конфиги, полные выводы `device_status`, рабочие названия проектов, URI частных сервисов, receipts или скриншоты действующих задач.
