# Установка и первая настройка

## Требования

Для ядра нужен Node.js 22.12 или новее. Git нужен для клонирования и дальнейшей разработки. Windows launcher рассчитан на Windows; прямой stdio-запуск и синтетические тесты также используются на Linux.

WSL, Codex Connect, tunnel-клиент и MCP-адаптеры приложений устанавливаются отдельно и требуются только для соответствующих функций. Сам агент не устанавливает эти продукты.

## 1. Получить код и проверить пакет

```bash
git clone https://github.com/getcher123/MSI-remote-agent.git
cd MSI-remote-agent
npm test
npm run check:privacy
npm run check:routes
npm run build:manifest
npm run validate
```

Сервер использует встроенные модули Node.js. `npm install` для этих команд не требуется.

## 2. Создать локальную конфигурацию

Для первой проверки можно разрешить работу только с клонированным каталогом:

```bash
npm run configure -- --root .
node server/index.mjs --self-test
```

`configure` разрешает существующий каталог в абсолютный canonical path и записывает приватную конфигурацию вне checkout. Без `--root` выбирается текущий каталог. Для рабочего применения укажите нужный существующий каталог при запуске; повторение `--root` позволяет выбрать несколько корней.

Для ограничения **файловых инструментов** чтением выберите этот вариант вместо предыдущего:

```bash
npm run configure -- --root . --read-only
```

Это не запрещает запись произвольным программам: процессные инструменты отдельно регулируются `commandPolicy` и работают с правами OS-пользователя.

По умолчанию конфигурация находится в `%LOCALAPPDATA%\AIHubRemoteAgent\config.json` на Windows или `~/.aihub-remote-agent/config.json` на другом хосте. `AIHUB_REMOTE_AGENT_CONFIG` позволяет выбрать другой файл вне репозитория. Команда не перезаписывает существующий конфиг: при дальнейших изменениях отредактируйте его явно и проверьте self-test. Не копируйте этот файл в Git.

В конфигурации из исходников `allowedRoots` пуст, WSL и Codex выключены. Диагностика может запускаться до настройки, но файловый доступ не предоставляется. `configure` добавляет только выбранные вами корни; домашние каталоги и конфигурации других клиентов автоматически не открываются.

## 3. Выбрать способ подключения

### Локальный stdio-клиент

Команда сервера из корня проекта:

```bash
node server/index.mjs --stdio
```

Она ожидает MCP JSON-RPC по stdin; это не интерактивная консоль с приглашением. Укажите клиенту этот executable/аргументы и рабочий каталог проекта. Пакетный `mcp.json` содержит такое же определение для plugin-хоста с поддержкой `PLUGIN_ROOT`. Не отправляйте диагностический текст в stdout сервера.

### Windows launcher и туннель

После создания конфигурации и проверки манифеста выполните в Windows PowerShell:

```powershell
.\launcher\AIHub-Remote-Agent-Install.cmd
```

Установка создаёт отдельную версию кода и `current`, сохраняя существующий конфиг. Если конфигурация ещё не создана, сначала выполните шаг 2 из выбранного checkout/workspace. Копирование каталога проекта само по себе не обновляет действующую установку.

Для удалённого подключения используется отдельно устанавливаемый OpenAI Secure MCP Tunnel. Нужны доступный `tunnel_id`, runtime API key, разрешения Platform для использования туннеля и разрешение рабочего пространства на custom MCP. Создание и использование туннеля имеют разные роли. Актуальные условия: [официальная инструкция Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).

Получите tunnel-клиент по ссылке в Platform или из [официальных релизов](https://github.com/openai/tunnel-client/releases/latest), поместите `tunnel-client.exe` в PATH и выполните:

```powershell
.\launcher\AIHub-Remote-Agent-Configure-Tunnel.cmd
.\launcher\AIHub-Remote-Agent-Start.cmd
```

Первый скрипт запросит реальный tunnel ID и настроит профиль `aihub-remote-agent` для текущего установленного сервера. Второй выполнит self-test и doctor, запросит runtime key локально и запустит туннель. Ключ не записывается launcher-скриптом в файл; не вводите его в issue или чат.

В ChatGPT добавьте custom MCP server через раздел Plugins, выберите Tunnel и нужный туннель, затем проверьте обнаруженные инструменты. Точные шаги и ограничения рабочего пространства приведены в [официальной инструкции подключения](https://developers.openai.com/plugins/deploy/connect-chatgpt). После подключения вызовите `device_status` и сопоставьте каталог с [TOOLS.md](TOOLS.md).

## 4. Включать интеграции по мере необходимости

### WSL

При первоначальном создании конфигурации можно передать **вместе** `--wsl-distro` и `--wsl-user`. Ниже PowerShell запрашивает реальные значения локально; выполните этот вариант шага 2 только если конфигурация ещё не создана:

```powershell
wsl.exe --list --quiet
$agentWslDistro = Read-Host 'Имя установленной WSL distribution'
$agentWslUser = Read-Host 'Имя пользователя в выбранной distribution'
npm run configure -- --root . --wsl-distro $agentWslDistro --wsl-user $agentWslUser
```

Уже существующий конфиг редактируется отдельно: `wsl.enabled=true`, точные `distro` и `user`. Разрешённые WSL-корни задаются явно; включение WSL не даёт доступ ко всему домашнему каталогу. Для native-команд используйте `runtime=native`; `windows` сохраняется как совместимое прежнее имя runtime, `wsl` выбирает настроенную distribution.

### Codex Connect

Сначала проверьте внешние адаптер и UI sender по [контракту](CODEX_CONNECT_COMPATIBILITY.md). В приватном конфиге задайте `codex.enabled=true`, абсолютные WSL-пути `adapterPath` и `uiSenderPath`, проверенные SHA-256 `adapterSha256` и `uiSenderSha256`, а также включённый WSL. `messageDir` можно задать явно; иначе он выводится из настроенного WSL-пользователя. Не используйте хеши или пути другой машины.

Выполните `codex_doctor` и exact-thread read. Отправка тестового сообщения — отдельная разрешённая проверка, её не делает установка.

### Локальные MCP

Настройте источник и разрешённые пути по [LOCAL_MCP_RU.md](LOCAL_MCP_RU.md). Явно выберите нужный сервер, получите его схемы, выполните разрешённую пробу и проверьте отключение. Если WSL выключен и `localMcp.sources` пуст, автоматического поиска в домашнем Codex-конфиге нет.

## Проверка готовности

Локальный self-test подтверждает базовую работоспособность сервера. Проверка туннеля подтверждает транспорт. Каждый реально используемый MCP и Codex UI требует собственного сценария. Сохраните только очищенную сводку проверки; конфигурация и полные ответы остаются локально.

Для обновления существующей установки и возврата предыдущего кода используйте [UPGRADE_RU.md](UPGRADE_RU.md).
