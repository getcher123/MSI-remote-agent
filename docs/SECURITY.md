# Безопасность и конфиденциальность

## Модель доверия

Агент предназначен для доверенного пользователя и разрешённых им задач. Он работает с правами своей учётной записи ОС. Доступ к инструментам позволяет выполнять команды, поэтому учётную запись, MCP-клиент и туннель нужно выбирать с учётом этих прав.

Файловые инструменты проверяют канонические разрешённые корни, запрещённые фрагменты пути и выход через symlink/junction. Точные правки защищаются ожидаемым SHA. Эти проверки не образуют песочницу для произвольного кода: разрешённые PowerShell, Python, Node.js или Bash способны обращаться к ресурсам, доступным их OS-пользователю. `intent=read` — заявленное намерение, не технический запрет записи.

`confirm_mutation=true` подтверждает намерение вызывающей стороны на уровне контракта инструмента. Оно не является независимой проверкой личности и не заменяет разрешение пользователя на конкретную задачу. Уже данное разрешение не нужно спрашивать заново перед каждым техническим шагом.

## Локальные MCP

- Регистрируются только явно выбранные определения. Регистрация не расширяет разрешённые пути или список исполняемых файлов.
- Сохраняется ссылка на источник и отпечаток определения. Изменение определения блокирует использование до пересмотра регистрации.
- Ограничения `enabled_tools` и `disabled_tools` исходной конфигурации учитываются.
- Перенаправления HTTP, credentials в userinfo URL и подмена управляемых протокольных заголовков отклоняются.
- Внутренние MCP-процессы не выдаются через публичные terminal sessions и не пишут сырые протокольные логи процесса.
- Подсказки, ресурсы, названия и описания стороннего сервера — внешние данные; они не дают разрешения на новые действия.
- `operation_id` защищает от повтора данного ID, но не от одинакового действия с новым ID и не от повторов внутри стороннего сервера.

## Что остаётся приватным

Локальная конфигурация может содержать пользовательские пути и ссылки на источники credentials. Полные MCP-результаты, Codex-квитанции и вывод процессов могут содержать документы, сообщения, изображения и другие частные данные. Они не очищаются автоматически от секретов и не удаляются по сроку хранения.

Метаданные аудита ограничены allowlist и не включают тела сообщений, файлы, stdin, значения окружения, argv или текст исключений. Обычный stdout/stderr дочернего процесса сохраняется локально и может содержать всё, что напечатал процесс. Не запрашивайте вывод токенов, cookies, приватных ключей или полного окружения.

Launcher не записывает tunnel runtime key в файл. `CONTROL_PLANE_API_KEY` удаляется из окружения дочерних рабочих процессов без учёта регистра имени. Остальное наследуемое окружение не является исчерпывающе отфильтрованным. Защищайте каталог состояния средствами ОС; код не обещает исправить произвольные ранее выставленные Windows ACL.

В публичный Git не должны попадать конфигурация реальной машины, `.env`, ключи, записи туннеля, личные пути, переписка, screenshots, runtime state и сырые отчёты. Проверка пакета и сканирование помогают находить ошибки, но не заменяют ревью фактического diff.

## Процессы, квитанции и обновления

Остановка относится только к процессам, которыми владеет агент; для WSL проверяются PID, время старта, UID, PGID и session. Отделившийся дочерний процесс с новой session находится вне гарантии. Заявленный запрос остановки не равен подтверждённому завершению.

Квитанции Codex сохраняются до UI-вызова. Неразрешённый исход блокирует новую отправку в тот же thread. Повреждённые квитанции и устаревшие lock-файлы не сбрасываются автоматически. Сначала нужна проверка живого владельца и фактического состояния приложения.

SHA-манифест проверяет целостность относительно самого манифеста. Он не является подписью издателя. Код, конфигурация и runtime state имеют разный жизненный цикл: откат кода не отменяет уже выполненные внешние действия.

## Сообщение об уязвимости

Не раскрывайте уязвимость с приватными данными в публичном issue. Если на вкладке Security доступно **Report a vulnerability**, используйте приватное сообщение GitHub. Если приватный канал не включён, откройте issue только с просьбой предоставить такой канал, без подробностей эксплуатации или секретов.

Для обычной ошибки достаточно синтетического примера, версии и безопасного кода ошибки. Если секрет уже опубликован, отзовите или замените его у соответствующего провайдера; удаление файла из нового коммита не удаляет старую Git-историю.
