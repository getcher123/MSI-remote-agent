# Эксплуатация и восстановление

## Обычная работа

Начните с `device_status`. Убедитесь, что подключено ожидаемое устройство и версия, затем выберите маршрут из [каталога инструментов](TOOLS.md). Полный ответ диагностики содержит локальные сведения; не публикуйте его в issue.

Для файлов используйте структурированные инструменты и актуальный SHA. Для процесса сохраните session ID и читайте вывод по возвращённым offsets. Для локального MCP сначала получите реальную схему инструмента. Для Codex используйте точный UUID и квитанцию отправки.

## Windows launcher

| Команда | Назначение |
| --- | --- |
| `launcher\AIHub-Remote-Agent-Install.cmd` | Проверить манифест и установить версию |
| `launcher\AIHub-Remote-Agent-Configure-Tunnel.cmd` | Настроить локальный профиль tunnel-клиента |
| `launcher\AIHub-Remote-Agent-Start.cmd` | Проверить локальный агент и запустить туннель |
| `launcher\AIHub-Remote-Agent-Status.cmd` | Проверить установленный экземпляр и записанный процесс |
| `launcher\AIHub-Remote-Agent-Stop.cmd` | Остановить процесс туннеля после проверки владения |
| `launcher\AIHub-Remote-Agent-Rollback.cmd` | Вернуть предыдущую установленную версию кода |
| `launcher\AIHub-Remote-Agent-Uninstall.cmd` | Удалить установку, конфигурацию и состояние после явного локального подтверждения |

Uninstall удаляет локальные данные и не используется для обновления или отката. Сначала сохраните нужную приватную резервную копию и проверьте завершение процессов.

Запускайте команды из доверенного checkout или установленной версии. Не используйте kill-by-name для остановки Node.js, приложений или WSL.

## Диагностика

| Симптом | Действие |
| --- | --- |
| Интеграция отключена / не настроена | Проверить локальный конфиг; ядро может работать без WSL/Codex |
| Файл вне allowed root | Сверить цель и права. Изменять корни только для разрешённой задачи, не обходить через shell |
| SHA mismatch | Перечитать файл, понять чужое изменение, построить новую правку |
| Новый вывод потерян или обрезан | Использовать offsets, `base_offset`, `lost_chars` и `has_more`; не объявлять неполный журнал полным |
| Process stop запрошен, выхода нет | Читать статус и `termination_confirmed`; не считать успешный сигнал завершением |
| MCP source/fingerprint changed | Завершить операции, отключиться, проверить изменения источника и перерегистрировать его |
| MCP reconnect required | Проверить незавершённые операции; явно отключить старое соединение и подключиться снова |
| MCP outcome unknown | Читать тот же operation ID и состояние приложения; не повторять действие с новым ID |
| Codex title неоднозначен | Выбрать по проверенному UUID, title и cwd |
| Codex send не подтверждён | Читать исходный receipt ID; не отправлять сообщение повторно |
| Lock после аварии / повреждённая квитанция | Проверить владельца и приложение, сохранить приватную копию состояния, разбирать вручную; не сбрасывать автоматически |
| Туннель недоступен | Разделить локальный self-test и диагностику tunnel-клиента; проверить профиль без вывода ключей |

## Перезапуск и очистка

Перед перезапуском завершите или сверяйте собственные активные процессы и операции. Обычные process sessions не восстанавливаются из памяти после рестарта; квитанции сохраняются. Наличие квитанции не гарантирует, что внешнее приложение всё ещё выполняет задачу.

Очищайте локальное состояние только после завершения и сверки операций. Автоматический срок хранения пока не реализован. Не удаляйте незавершённые квитанции и locks для обхода ограничений. Откат выполняется по [UPGRADE_RU.md](UPGRADE_RU.md).
