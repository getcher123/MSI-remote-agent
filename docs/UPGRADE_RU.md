# Обновление и откат

Версионный Windows launcher хранит код в каталоге `releases`, а конфигурацию и runtime state — отдельно. Junction `current` выбирает активный код. Установщик сверяет SHA-манифест и не принимает другой набор файлов под уже установленной версией.

## Обновление

1. Завершите или сверяйте активные операции. Сохраните приватную резервную копию конфигурации и состояния средствами ОС, вне репозитория.
2. Выполните `launcher\AIHub-Remote-Agent-Stop.cmd` и проверьте статус. Не обновляйте код под работающим записанным tunnel-процессом.
3. В новом доверенном checkout/пакете выполните тесты и валидацию. Если манифест ещё не создан после изменений, пересоберите его.
4. Запустите `launcher\AIHub-Remote-Agent-Install.cmd`. Существующая конфигурация сохраняется; изучите новые настройки отдельно.
5. Запустите `launcher\AIHub-Remote-Agent-Start.cmd` и проверьте `device_status`.
6. Если подключённый MCP-клиент кэширует каталог, обновите каталог инструментов в интерфейсе клиента и сравните с [TOOLS.md](TOOLS.md).
7. Выполните нужный сценарий приёмки: файлы, процесс, конкретный локальный MCP или Codex. Не переносите результат старого smoke на новую сборку без проверки.

При существующем корректном профиле, который указывает на `current`, обычно достаточно перезапуска. Облачную привязку и credentials установщик не меняет.

## Откат

Запустите `launcher\AIHub-Remote-Agent-Rollback.cmd`, затем Start и `device_status`. Скрипт проверяет предыдущий пакет и переключает код. Для отката должна существовать ранее установленная версия с валидным манифестом.

Откат сохраняет конфигурацию и состояние. Он не отменяет изменения файлов, действий сторонних MCP и уже доставленных сообщений. После изменения формата состояния отдельно проверяйте обратную совместимость; необходимость миграции должна быть описана в changelog соответствующей версии.

Не удаляйте старую версию до проверки новой и сценария возврата. Не переиспользуйте номер версии для других байтов пакета.
