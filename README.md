# AIHub Remote Agent

[![Tests](https://github.com/getcher123/MSI-remote-agent/actions/workflows/test.yml/badge.svg)](https://github.com/getcher123/MSI-remote-agent/actions/workflows/test.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

**Локальный MCP-агент для работы AI-помощников с файлами, терминалом, Codex Connect и MCP-серверами приложений.** Агент запускается на вашем компьютере и предоставляет 30 инструментов через MCP `stdio`. Для удалённого подключения нужен отдельный поддерживаемый транспорт, например Secure MCP Tunnel.

Название репозитория — `MSI-remote-agent`; имя проекта и пакета — **AIHub Remote Agent**. Для работы не требуется компьютер определённой марки. Версия исходников **0.3.2** содержит универсальную настройку, восстановление статуса Codex-отправки по заранее известному ID и совместимость с ранее сохранёнными решениями владельца по старым квитанциям. Рабочая конфигурация в пакет не входит. Изменение исходников не означает обновление установленного агента; проверенные сценарии и открытые ограничения перечислены в [state.md](state.md).

> **English:** A local MCP agent for authorized file operations, native/WSL processes, optional Codex Connect and explicitly registered MCP servers. Windows launchers support installation, upgrades and rollback. Configuration, credentials and runtime state stay outside the source repository. See [architecture](docs/ARCHITECTURE.md) and [contributing](CONTRIBUTING.md).

## Что умеет

| Задача | Возможность |
| --- | --- |
| Работать с файлами | Просмотр каталогов, чтение текста и бинарных фрагментов, запись, точное редактирование и перемещение внутри разрешённых корней |
| Выполнять команды | Запуск разрешённых программ, PowerShell и WSL; чтение stdout/stderr, ввод в stdin и проверяемая остановка собственных процессов |
| Подключать MCP приложений | Обнаружение конфигураций, явная регистрация сервера, получение настоящих схем, вызовы инструментов, resources и prompts |
| Работать с Codex Connect | Проверка внешнего адаптера, поиск и чтение точной сессии, отправка сообщения с проверкой доставки |
| Обновлять Windows-установку | Проверка manifest, отдельные каталоги версий, сохранение локальной конфигурации и возврат к предыдущей версии |
| Продолжать разработку агентами | [AGENTS.md](AGENTS.md), [операционный skill](skills/remote-machine/SKILL.md), [план развития](ROADMAP.md), CI и проверки публикации |

Blender, Roblox, Adobe и другие приложения доступны **при наличии совместимого, установленного и настроенного MCP-сервера этого приложения**. Встроенных универсальных драйверов этих программ здесь нет. Наличие каталога инструментов ещё не подтверждает выполнение конкретной операции в приложении.

## Быстрый старт из исходников

Нужны Git и **Node.js 22.12+** с npm. В runtime нет сторонних npm-зависимостей: `npm install` для запуска не требуется.

В PowerShell, CMD или терминале Linux:

```sh
git clone https://github.com/getcher123/MSI-remote-agent.git
cd MSI-remote-agent
npm run configure -- --root .
npm run self-test
npm run check
```

Команда `configure` разрешает работу с текущим каталогом проекта и сохраняет персональную конфигурацию **вне репозитория**:

- Windows: `%LOCALAPPDATA%\AIHubRemoteAgent\config.json`.
- Linux: `~/.aihub-remote-agent/config.json`.

Существующая конфигурация не перезаписывается. Если она уже есть, проверьте её локально и переходите к `self-test`. Для нескольких рабочих каталогов можно повторить аргумент `--root`; `npm run configure -- --help` показывает полный синтаксис. Опция `--read-only` выдаёт файловым инструментам только право чтения; команды терминала всё равно выполняются с правами пользователя ОС.

WSL и Codex Connect изначально выключены. Поставляемый `config/default-config.json` не разрешает ни одного каталога. Если запустить агент до настройки, `self-test` покажет `setup_required: true`; это не подтверждение готовности интеграций.

### Подключение к локальному MCP-клиенту

Точка входа:

```sh
node server/index.mjs --stdio
```

Это сервер протокола, а не интерактивная командная оболочка. Его должен запускать MCP-клиент. В пакете есть [mcp.json](mcp.json) для клиентов, поддерживающих формат Agent Plugins и переменную `${PLUGIN_ROOT}`. Для другого клиента укажите фактический абсолютный путь к `server/index.mjs` в его локальных настройках; не добавляйте этот персональный файл в Git.

### Установка на Windows и удалённое подключение

После проверки исходников выполните в PowerShell:

```powershell
.\launcher\AIHub-Remote-Agent-Install.cmd
```

Установщик использует проверенный `release-manifest.json`, хранит версии в `%LOCALAPPDATA%\AIHubRemoteAgent\releases` и сохраняет существующие конфигурацию и состояние. Локальный MCP можно использовать без туннеля. Для подключения из ChatGPT настройте туннель по [инструкции установки](docs/INSTALLATION.md), затем используйте:

```powershell
.\launcher\AIHub-Remote-Agent-Configure-Tunnel.cmd
.\launcher\AIHub-Remote-Agent-Start.cmd
```

`Configure-Tunnel` нужен для новой настройки или изменения профиля. Для уже настроенного профиля достаточно `Start`. Права доступа к внешнему сервису, его клиент и учётные данные предоставляются отдельно. Ключ вводится локально и не должен попадать в Git, чат, скриншот или issue.

## Дополнительные интеграции

### Терминал и WSL

`start_process` принимает `runtime: "native"` для текущей ОС, `"windows"` для совместимости с прежними клиентами и `"wsl"` для явно настроенного WSL на Windows. PowerShell вызывается как программа `powershell.exe` или `pwsh` с массивом аргументов. `cwd` должен входить в разрешённые корни, а исполняемая программа — в allowlist.

WSL включается парой параметров `--wsl-distro` и `--wsl-user` при первоначальной настройке либо изменением приватного конфига. Настройка WSL не добавляет файловых разрешений автоматически. Когда агент уже запущен внутри Linux/WSL, используйте `native`.

### MCP приложений

Путь агента: `local_mcp_discover` → `local_mcp_register` → `local_mcp_tools` → разрешённый вызов `local_mcp_call` → проверка `local_mcp_operation`.

Сервер регистрируется явно из локального JSON/TOML-конфига. Перед запуском проверяются разрешённые пути и команды. Доступны `stdio` и поддерживаемый вариант Streamable HTTP; legacy SSE не поддерживается. Получение каталога может запускать зарегистрированный процесс. Каждое действие имеет `operation_id`: при неопределённом результате действие не повторяется автоматически.

Подробности, ограничения протокола и команды CLI: [локальный MCP](docs/LOCAL_MCP_RU.md).

### Codex Connect

Это **необязательная интеграция с внешним адаптером**, который не поставляется в этом репозитории. Для нового явного включения требуются настроенный WSL, реальные пути к адаптеру и UI sender, а также SHA-256 проверенных файлов.

`codex_doctor` проверяет адаптер, но не доказывает доставку сообщения. Отправка требует точного UUID сессии, совпадения title/cwd, известного статуса `idle` и отсутствия pending requests и неподтверждённых submissions.

Перед первым вызовом `codex_send_message` создайте и сохраните `operation_id`, затем передайте его вместе с полным текстом сообщения. Агент сохраняет квитанцию до проверки скриптов и первого IPC-чтения. Потерянный ответ можно восстановить через `codex_delivery_status` по этому ID; повтор ID не запускает отправку заново. Прежние клиенты без `operation_id` поддерживаются, но не имеют заранее известного ключа восстановления ответа.

Во время активной отправки `codex_delivery_status` по умолчанию возвращает сохранённый этап без ожидания IPC. `refresh=false` всегда читает квитанцию, `refresh=true` явно сверяет неизвестную доставку с живой сессией без отправки. Статус `queued`, тайм-аут, пустой composer и отсутствие сообщения в текущем хвосте не подтверждают доставку или её отсутствие. Не повторяйте неизвестную отправку с новым ID и не удаляйте блокировку для обхода сверки.

Сообщение ограничено **32768 байтами UTF-8**. Полный диапазон чтения требует совместимого парного адаптера: `--timeout` 1..60, discovery `--limit` 1..200, read `--limit` 1..20 и `--max-chars` 100..200000. Внешние скрипты и их SHA обновляются отдельно; старые пределы CLI не расширяются одним обновлением MSI.

Контракт и границы поддержки: [Codex Connect compatibility](docs/CODEX_CONNECT_COMPATIBILITY.md).

## Инструменты MCP

| Группа | Инструменты |
| --- | --- |
| Диагностика — 1 | `device_status` |
| Файлы — 7 | `list_directory`, `file_info`, `read_file`, `read_multiple_files`, `write_file`, `edit_file`, `move_file` |
| Процессы — 5 | `start_process`, `process_output`, `process_input`, `list_process_sessions`, `terminate_process` |
| Codex — 5 | `codex_doctor`, `codex_discover`, `codex_read_thread`, `codex_send_message`, `codex_delivery_status` |
| Локальные MCP — 12 | `local_mcp_discover`, `local_mcp_register`, `local_mcp_servers`, `local_mcp_tools`, `local_mcp_call`, `local_mcp_operation`, `local_mcp_resources`, `local_mcp_read_resource`, `local_mcp_prompts`, `local_mcp_get_prompt`, `local_mcp_disconnect`, `local_mcp_unregister` |

Параметры определяются схемами `tools/list`. [Справочник инструментов](docs/TOOLS.md) объясняет назначение и порядок использования. Для агентского продолжения разработки начните с [AGENTS.md](AGENTS.md); для управления машиной — с [remote-machine](skills/remote-machine/SKILL.md).

Долгий вызов инструмента не задерживает `ping`, handshake, `tools/list` и чтение квитанций через `codex_delivery_status` / `local_mcp_operation`. Остальные вызовы инструментов сохраняют последовательное исполнение. Это устраняет блокировку управления внутри stdio-сервера; поведение внешнего туннеля, включая ответ HTTP 409, требует отдельной проверки и не объявлено исправленным.

## Безопасность и конфиденциальность

- Файловые инструменты проверяют разрешённые корни и realpath. Перезапись существующего файла требует ожидаемого SHA-256; изменения требуют `confirm_mutation: true`.
- Агент и запущенные им программы работают с правами пользователя ОС. Allowlist, фильтры команд и `intent: "read"` не создают системную песочницу. Настраивайте доступ под доверенных операторов и конкретные проекты.
- Метаданные аудита фильтруются, но вывод процессов и ответы внешних MCP могут содержать секреты или рабочие данные. Runtime state, квитанции и логи не являются публичными артефактами.
- В репозитории есть `.gitignore`, сканер распространённых секретов/персональных путей и явный перечень публикуемых файлов. Проверка выдаёт имя файла, строку и правило без печати найденного значения. Она дополняет ручную проверку, не гарантирует обнаружение любой конфиденциальной информации.

Политика сообщения об уязвимостях: [SECURITY.md](SECURITY.md). Практические границы: [модель угроз](docs/THREAT_MODEL.md).

## Обновление и откат

Не заменяйте исходники внутри установленного каталога версии. Для нового сборочного содержимого используйте новую версию и пересозданный manifest. Установка поверх той же версии с другим manifest отклоняется.

После установки следующей версии вернуться к предыдущей можно командой:

```powershell
.\launcher\AIHub-Remote-Agent-Rollback.cmd
```

Откат переключает код; персональная конфигурация и runtime state сохраняются. При изменении формата данных нужно отдельно проверить совместимость. Порядок остановки, обновления и проверки: [UPGRADE_RU.md](docs/UPGRADE_RU.md).

## Разработка и проверки

```sh
npm run check:privacy
npm run check:routes
npm test
npm run build:manifest
npm run validate
```

После изменения исходников manifest нужно пересоздать перед `npm run check`. Проверка маршрутов сопоставляет зарегистрированные инструменты с операционным skill и проверяет относительные Markdown-ссылки. Manifest воспроизводим: одинаковые файлы дают одинаковое содержимое без временной метки.

GitHub Actions запускает проверки на Ubuntu и Windows с Node.js 22 и 24. На Windows дополнительно выполняются изолированные проверки процессов, установки, обновления и отката. Настоящие WSL, туннель, Codex UI и MCP конкретных приложений требуют отдельной проверки на целевой машине. Зелёный CI не заменяет такую приёмку.
