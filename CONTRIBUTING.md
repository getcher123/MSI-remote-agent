# Участие в разработке

Проект развивается как небольшой, проверяемый MCP-агент. Перед изменением прочитайте [AGENTS.md](AGENTS.md), [архитектуру](docs/ARCHITECTURE.md) и [границы безопасности](docs/SECURITY.md).

## Локальная работа

Нужен Node.js версии, указанной в `package.json`. Сервер использует встроенные модули Node.js; устанавливать зависимости для запуска тестов не требуется.

```bash
git clone https://github.com/getcher123/MSI-remote-agent.git
cd MSI-remote-agent
npm test
npm run check:privacy
npm run check:routes
npm run build:manifest
npm run validate
node server/index.mjs --self-test
```

Для работы с реальными файлами сначала выполните настройку по [инструкции](docs/INSTALLATION.md). Для автоматических тестов используйте временные каталоги и синтетические данные. Не направляйте тесты на действующие приложения или рабочие Codex-сессии.

## Что должно быть в изменении

1. Короткое описание проблемы и нового поведения.
2. Небольшой diff, относящийся к одной задаче.
3. Проверка затронутого поведения. Для исправления ошибки нужен тест, воспроизводящий её; для простого текста достаточно проверки ссылок и команд.
4. Обновлённая документация при изменении инструмента, конфигурации или ограничений.
5. Фактические результаты тестов с указанием пропусков и непроверенных платформ.

Изменения транспорта, долговременных квитанций, управления процессами, прав доступа и упаковки требуют отдельного ревью. В pull request объясните сценарий отказа и поведение после перезапуска.

## Перед публикацией

Просмотрите весь staged diff, включая новые файлы. Не коммитьте локальный `config.json`, `.env`, токены, MCP-конфигурацию реального клиента, пользовательские пути, проекты, журналы, скриншоты или квитанции. Описывайте ошибки через синтетический пример. Манифест пересобирайте после окончательной правки файлов релиза.

Не обновляйте установленный экземпляр и не отправляйте тестовые сообщения в Codex в рамках обычного CI. Разрешение на такие действия должно относиться к конкретному стенду и сценарию.

## Сообщения об ошибках

Для обычной ошибки используйте issue-шаблон. Указывайте версию агента и Node.js, ОС, воспроизводимые шаги и безопасный код ошибки. Не прикладывайте полный `device_status`: он может содержать имя компьютера, локальные пути и конфигурацию интеграций.

Для уязвимости следуйте [политике безопасности](docs/SECURITY.md#сообщение-об-уязвимости). Не публикуйте секреты в issue, даже если считаете их тестовыми.
